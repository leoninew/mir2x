# GM 聊天命令

本文只收录在游戏聊天输入框直接发送的 `@` 命令。输入完整命令后按 Enter，操作当前登录角色。

## 常用操作

| 操作               | 聊天命令            |
| ------------------ | ------------------- |
| 查看命令清单       | `@help`             |
| 传送到比奇地图     | `@moveTo 1`         |
| 传送到比奇指定坐标 | `@moveTo 1 414 349` |
| 增加一级           | `@addLevel 1`       |
| 增加 1000 经验     | `@addExp 1000`      |
| 恢复生命与魔法     | `@xcg`              |
| 获得两把木剑       | `@makeItem 木剑 2`  |

**当前没有给自己或指定角色加金币的聊天命令。** `@makeItem` 不能增加金币余额。服务端加金币的脚本用法单独放在 [Lua 调试脚本](lua-debugging.md#给自己的角色加金币)，不属于聊天命令。

## 权限

源码 `uidf::isGM(uid)` 将玩家 DBID ≤ 10 定义为 GM，但当前聊天命令入口及相关协议处理没有统一执行这一权限检查。

## 客户端 `@` 命令

在聊天输入框输入完整命令并提交。命令名区分大小写，支持**唯一前缀**缩写，例如 `@make` 匹配 `makeItem`。`@add` 同时匹配多个命令，会报歧义并列出候选。参数仅按 ASCII 空格分隔，没有通用的引号或转义解析。

| 完整命令                | 参数与行为                                                                               |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| `@help`                 | 列出实际注册的命令名，不显示详细参数帮助                                                 |
| `@moveTo`               | 当前地图实例内随机位置传送                                                               |
| `@moveTo x y`           | 当前地图实例内指定坐标传送                                                               |
| `@moveTo mapID`         | 指定地图的基础实例内随机位置传送                                                         |
| `@moveTo mapID x y`     | 指定地图的基础实例内指定坐标传送                                                         |
| `@makeItem 物品名 数量` | 按物品记录名称造物并交给服务器加入背包；当前 `@` 实现要求显式数量 **大于 1**，见下文缺陷 |
| `@getAttackUID`         | 在聊天日志中输出当前攻击焦点 UID                                                         |
| `@addHP 数值`           | 请求增加 HP；服务器把负数截为 0，死亡角色收到正 HP 时可原地复活                          |
| `@addMP 数值`           | 请求增加 MP；服务器把负数截为 0，仅加 MP 不会复活                                        |
| `@xcg`                  | 以当前已知最大 HP/MP 为增量请求恢复；客户端没有健康数据时不发送                          |
| `@addExp 数值`          | 增加经验；应使用正常范围内的正整数，当前参数转换没有完整的错误处理                       |
| `@addLevel 正整数`      | 按“当前等级 + 增量”计算目标等级，再补足到该等级的累计经验；不是直接改等级字段            |
| `@killPets`             | 请求杀死自己控制的宠物                                                                   |
| `@die`                  | 请求角色死亡                                                                             |
| `@luaEditor`            | 仅提示 Lua 编辑器尚未实现                                                                |

`moveTo` 是空间移动请求，不是寻路走路。客户端先检查坐标与地块可通行性，服务器再处理同图移动或换图，并在成功后更新数据库位置。输入的是地图记录 `mapID`，不是地图实例 `mapUID`。聊天中出现 “sent” 只说明请求已发送。

`addLevel` 限制目标等级不超过 `SYS_MAXLEVEL`，当前常量为 1024。命令处理大多直接调用 `stoi/stol`，不要把无效字符串、负经验或极大整数当作受支持用法。

### 可对照的输入示例

```text
@help
@getAttackUID
@addHP 100
@addMP 100
@xcg
@addExp 1000
@addLevel 1
@makeItem 木剑 2
@moveTo 1
```

例如，`@moveTo 1` 会传送到地图 ID `1`（地图记录名 `比奇县_0`，即比奇地图）的基础地图实例内随机可通行位置。

若角色当前就在 `比奇县_0`，也可用 `@moveTo 414 349` 请求传送到该图坐标；这是文档中比奇商人所在位置。指定地图及坐标的形式是 `@moveTo mapID x y`，例如 `@moveTo 1 414 349`。目标坐标必须是当前客户端地图数据认可的可通行点。这些都是传送请求，不是角色沿路径行走。

这些命令操作的是当前登录角色。加血复活走的是调试路径，与正常死亡后回城、恢复部分生命的 `CM_REQUESTREVIVE` 不同。

### `@makeItem` 的现有缺陷

帮助文本显示 `@make 物品名字`，但实际实现有两个问题：

- 省略数量时，内部默认值是 1，后续却只接受 `count > 1`；报错分支还访问不存在的第三个 token，存在越界访问风险。不要使用省略数量的 `@makeItem`。
- 显式数量为 1 也会被拒绝。聊天命令目前不能造单个物品。其他入口见 [Lua 调试脚本](lua-debugging.md)。

服务器会校验物品记录与数量，并按可堆叠性拆分物品；命令本身不扣除购买费用。本文只记录缺陷，没有修改实现。
