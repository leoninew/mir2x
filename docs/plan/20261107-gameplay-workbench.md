## 倍率设计

- 在 `server/config/gameplay/multipliers.json` 单独保存 schema_version=1、experience、gold、drop；独立 schema，三个字段为有限非负数，初始均为 1。
- 文件可缺省，兼容现有安装和历史备份。缺文件 revision 使用 `missing`，首次保存创建，避免覆盖后来出现的文件；没有原文件不制造单文件备份。
- C++ 启动快照增加只读倍率结构。经验在原伤害分配、最低值和取整后乘新倍率，再四舍五入，0 可以得到 0；原 experienceRate 继续不启用。
- 金币/掉率在原算法输入处叠乘，保留分组、顺序、重复及金币随机浮动；零倍率显式短路。正数沿原最低 1 规则，超范围整数饱和到 int 上界，避免非法转换。零经验保留击杀事件，零金币不调用要求正数的金币拆分。
- Python 增加 multipliers 文档域，复用校验、保存、冲突、备份；Vue 使用独立倍率编辑器和小数输入组件，不改变原整数输入。保存后下次服务端启动生效。

## 配置与命令设计

1. Dynaconf 写入覆盖值时将嵌套键统一为小写，避免默认 YAML 未声明的 gameplay 分支产生大写 ROOT；增加 dotenv 和环境变量回归测试。
2. 始终读取默认 YAML（或 EXE 旁的显式 YAML），叠加 `.env.<profile>`，最后叠加环境变量。profile 由外部选择，源码默认 dev，不加入 YAML。
3. Makefile 保留六个业务目标，默认 help 打印命令和 prod 覆盖示例，以 `profile=dev` 导出统一环境。前端构建采用所选模式。
4. 制品通过生成的 PyInstaller 启动钩子为 profile 提供默认值，显式环境变量仍优先；YAML 原样打包，不内嵌 dotenv。`binary` 构建后安装 workbench 组件；使用主构建缓存记录的 CMake 路径，兼容 Cygwin PATH。
