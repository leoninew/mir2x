## Technical decisions / 技术设计与决策

- 使用已有依赖 nlohmann JSON，文件名 `accounts.json`。通过 `SDL_GetBasePath()` 定位客户端所在目录，不依赖启动时的工作目录。文件包含 `schema_version: 1` 及 `accounts` 数组，每项仅有 `id`、`password`；不包含服务器维度。
- 保存普通 JSON 数据，先写同目录 `accounts.json.tmp`，关闭文件后用 SDL3 的 `SDL_RenamePath()` 替换正式文件。运行记录及临时文件加入 Git 忽略规则，不提供含真实账号的默认文件。
- 保存时按完整账号名精确匹配；同名更新密码并移到首位，新账号插入首位。重新进入登录页预填首项。有记录时默认勾选“记住账号”，无记录时默认不勾选；取消勾选只影响本次提交，不删除旧记录。
- 在账号输入框尾部内嵌上下箭头，多于一个已存账号时可用，否则保持低对比禁用状态以稳定布局。箭头循环切换列表；当前手工输入不在列表时从首项开始。切换同时填入对应密码，不提交请求，不改变勾选值。
- `sendLogin()` 保存实际发送的账号、密码及本次勾选值快照；等待响应时忽略重复登录提交。成功回调只保存快照，失败回调清除快照。收到响应前的输入或勾选变化不修改已提交快照。
- 既有 `--auto-login` 继续直接发送原参数，不因本地记忆功能自动落盘命令行凭据。手工输入及 Tab/Enter 沿用现有逻辑。
- 文件不存在时正常手工登录；读取异常时保留原文件，提示手工登录并停用本次记录保存。写入失败只记录不含账号密码的警告，正常进入选角，不影响登录结果。读取时检查版本、数组及现有协议的账号密码长度，避免异常本地数据破坏输入流程。
- 修订 2：保留背景插画及书法按钮素材，底部统一为深色渐入面板。上方三项辅助按钮居中等距排列；账号、密码采用等宽输入框，标签和输入区域按两列对齐；下方记忆选项与登录按钮同一中心线，分别对齐账号框左边缘和密码框右边缘，距窗口底边留足间距。输入框聚焦边框与切换箭头使用同一暖金配色。
