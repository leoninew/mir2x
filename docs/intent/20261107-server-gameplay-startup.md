## 背景与目标

当前feat/dev、HEAD ebfb8ca。安装版日志显示多个地图getMapSpawnConfig抛出gameplay configuration not initialized。main.cpp启动时已加载快照，但mainwindow.fl手动Launch回调删除该Server，再创建未初始化对象。地图脚本在定义main之前失败，无法启动刷怪协程。

修复手动启动的对象生命周期，使实际运行的Server保留启动时已验证的经验、掉落、刷怪及倍率快照；未初始化对象应在打开数据库、加载地图及启动actor前失败。

## 验收标准

- A01：实际FLTK Launch/密码确认回调不替换持有配置的Server，启动失败也保留同一完整快照。
- A02：没有玩法快照的Server::launch在任何数据库/地图/网络副作用前明确失败。
- A03：既有刷怪表、monGener与经验/掉落消费回归通过，服务端能够增量构建。
- A04：保留用户和其他会话的工作文件；不修改玩法初值、存档、角色或运行服务。构建安装与暂存按后续用户授权执行，只暂存本功能文件，不自行创建commit。

## 规模与边界

单一生命周期修复，无子任务。修改FLUID源而非生成的窗口文件；测试使用临时目录和实际窗口回调，数据库故意不可打开，避免真实网络和地图进程启动。配置目录含251地图的原数据保持。人工验收由用户自行完成，自动检查不连接现场。
