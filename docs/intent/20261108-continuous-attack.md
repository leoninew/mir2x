# Intent / 意图：持续攻击
最后修改时间: 2026-11-08 09:56:59

## Review status / 审查状态

Accepted

## Background and goals / 背景与目标

客户端点击怪物后已有连续普通攻击，但受击会清掉后续攻击动作，玩家必须重新点击。将游戏设置中尚未生效的“强制攻击”改为“持续攻击”，开启时在受击动作结束后继续攻击手动选择的同一怪物。

## Non-goals / 非目标

- 不自动寻找或切换目标，不增加自动施法、自动寻怪或自动 PvP。
- 不跳过受击动作，不改变服务端攻击判定、协议、数据库结构或现有攻击模式。

## Scenarios / 场景

- 点击怪物后受到攻击，受击动作播放完成，继续使用现有攻击与追踪逻辑。
- 关闭设置后，保留原先受击打断攻击的行为。
- 玩家移动、拾取地面物品、施法、对话或选择新目标时，以新操作为准；目标死亡或消失、自己死亡或换图时停止追踪旧目标。
- 使用设置复选框或 Shift+Tab 修改同一个配置；普通 Tab 仍拾取脚下物品。

## Acceptance criteria / 验收标准

- A01：设置名称为“持续攻击”，默认开启，沿用原配置的数字键和布尔类型，已有开关值可继续读取。
- A02：开启时仅对手动选中的怪物恢复受击后的攻击，受击动画结束前不注入恢复动作，复用原攻击链和寻路。
- A03：关闭时受击不恢复；未选目标或玩家目标不触发新的自动恢复。
- A04：主动操作、换目标、目标死亡或消失、角色死亡、传送及换图不会重新恢复旧目标；已有待处理动作优先。
- A05：Shift+Tab 切换且按键重复不重复切换，复选框和快捷键共享服务端持久化配置，并有系统聊天反馈；Tab 拾取保留。
- A06：相关自动检查和客户端构建通过，记录实机验证的覆盖范围及未验证项。

## Workload and decomposition / 工作量与拆分

工作量较小、复杂度中等，涉及原生客户端输入、动作队列、目标锁定和已有运行时配置。主要风险是错误地提前恢复而截断受击动作，或旧攻击回调覆盖新操作。这些修改共享同一目标生命周期，单会话实施并审查，不拆分 task；协调不适用。

## Questions and decisions / 问题与决策

- 名称采用“持续攻击”；用户已回复“采纳 … 记录后实现”。
- 采用已建议的 Shift+Tab，避免与现有 Tab 拾取冲突。
- 复用默认值为 true 的旧开关，在原声明位置重命名，保持持久化索引兼容。
- 无待用户确认的需求问题。

## Risks / assumptions / 风险 / 假设

- 现有动作触发器每帧运行，并非动画结束回调；恢复必须置于受击动作完成的切换入口。
- 自动检查不能代替真实客户端与服务端对打；未运行的实机场景须明确列出。
