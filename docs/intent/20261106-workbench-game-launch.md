# Intent / 意图：工作台启动客户端与服务端
最后修改时间: 2026-11-06 23:26:35

## Review status / 审查状态
Accepted。用户明确要求“Mir2xWorkbench.exe 要添加 client/server 启动能力”，并要求沿用主程序的install交付目录；沿用主会话直接实现与必要检查，不含Git提交或游戏实机启动。

## Background and goals / 背景与目标
当前GUI只编辑玩法文件。本变更提供受信桌面桥接及明确按钮，使用用户填写的相对EXE路径打开客户端/服务端窗口；各自以程序目录作为cwd。

## Non-goals / 非目标
不做停止/重启/自动登录/角色控制、构建部署、端口/并发配置、任意shell输入、HTTP远程启动。服务端打开原master窗口，是否启动服务仍由该窗口控制；不传--auto-launch，不访问凭据/用户数据库作开发检查。

## Scenarios / 场景
用户在GUI填写并保存客户端和服务端程序相对路径；以工作台EXE所在目录为基准解析，各程序以其自身目录为工作目录。默认值为../client/client.exe和../server/server.exe；可以使用../到同磁盘其他目录，不自动部署资源。

## Acceptance criteria / 验收标准
- A01：两个启动入口、程序路径/工作目录可见，浏览器模式明确不支持。
- A02：两个路径均作为GUI工作台配置，可修改并原子保存为相对路径；绝对路径、不同类型、缺文件明确报错；不提供shell/自动参数/自动部署。
- A03：使用固定argv及EXE所在cwd创建进程；同一工作台按角色串行防双击，不将OS创建成功称作游戏ready。
- A04：client/server路径统一持久保存在工作台目录game-launch.json；未保存路径禁止启动，当前页存在未保存玩法草稿时先提示，磁盘配置与管理目录不一致时明确显示。
- A05：只做必要静态检查、正常路径轻量检查及匹配GUI发行包检查；不追覆盖率，不做反向、UI或性能测试，不启动真实游戏/DB。

## Workload and decomposition / 工作量与拆分
小型跨Python/Vue变更，由主会话串行完成，不拆task、不派子agent。

## Questions and decisions / 问题与决策
无必须另询的意图问题。按“启动”最小范围实现，不推断停止或自动登录需求。以工作台目录为相对路径唯一基准；默认沿同级CMake安装布局。工作台与游戏生命周期独立，关闭工作台不结束游戏。

## Risks / assumptions / 风险 / 假设
Popen成功仅代表OS创建进程。端口冲突、资源版本、DB状态由游戏报告，工作台不承诺业务ready；跨工作台同时启动的竞争不在单实例锁保证内。UI通道不可用时不宣称目视完成。

- 用户随后明确：client/server路径也是GUI配置，使用相对路径且用户可自行修改。本意图以此替换原文件选择方案。
- 用户进一步明确不追覆盖率、不搞反向/UI/性能测试；本轮新增测试收敛为正常路径烟测，不改动既有测试。
- 用户实看截图后要求去掉“独白、免责声明”式界面。主视图以配置编辑和启动操作为主，路径表单进入单独设置弹窗；帮助只在设置或详情中出现，错误在对应操作后显示，保留必要字段校验和草稿确认。
- 用户明确工作台应服从主程序的install交付方式：正式入口改为`install/workbench/Mir2xWorkbench.exe`，构建中间目录不作为另一套运行安装。接入现有CMake安装，保留本地路径偏好、日志、玩法数据和存档；不关闭用户正在使用的旧dist工作台。
