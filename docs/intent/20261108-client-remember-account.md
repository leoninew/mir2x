# Intent / 意图：客户端记住账号与切换账号
最后修改时间: 2026-11-08 16:28:49

## Background and goals / 背景与目标

- 客户端登录页目前没有账号记忆功能，每次创建 `ProcessLogin` 都重新输入账号和密码。
- 在登录页添加“记住账号”勾选项。该选项记住的是登录成功的账号和密码，便于下次使用。
- 支持保存多个账号，在账号输入框旁提供上下按钮切换账号，同时填入该账号对应的密码。
- 账号记录作为普通本地数据，跟随客户端目录放置，不按服务器地址或端口区分。

## Non-goals / 非目标

- 不改服务端账号、认证协议或角色数据库，不把记忆数据放入 Workbench。
- 不增加服务器分组、账号管理页面或自动登录流程，不扩大为认证安全改造。
- 不自动提交代码。

## Scenarios / 场景

- 用户输入账号和密码，勾选“记住账号”后正常登录；收到登录成功回执后，客户端保存本次提交的账号和密码。
- 同一账号再次成功登录时，更新该账号的密码记录，不产生重复账号条目。
- 用户关闭并重新启动客户端，可以读取客户端目录内已保存的账号记录；通过账号框旁的上下按钮选择其他账号，账号与密码一起切换。
- 用户更换连接的服务端地址或端口，继续使用同一份本地账号记录。
- 用户未勾选“记住账号”时，本次登录不新增或更新已保存的账号密码；登录失败不保存本次提交内容。

## Acceptance criteria / 验收标准

- A01：登录页有“记住账号”勾选项，保存内容包含账号和密码，保存时机为收到 `SM_LOGINOK`。
- A02：保存本次实际发送的账号密码，不能在成功回执到达时读取已被用户改动的输入框内容作为保存值。
- A03：数据放在客户端目录内，能够跨客户端重启读取，不包含按服务器地址或端口隔离的维度。
- A04：账号框旁有上下切换按钮，可以切换已保存的账号；账号与密码保持配对，切换本身不发送登录请求。
- A05：相同账号按账号名更新记录；未勾选或登录失败时，不新增或更新本次账号密码。
- A06：保留现有手工输入、Tab/Enter、登录、注册、改密和退出功能；无已保存账号时仍可正常手工登录。
- A07：沿用必要的针对性检查，不追求测试覆盖率，不新增反向测试、UI 自动化测试或性能测试。

## Workload and decomposition / 工作量与拆分

工作量较小，职责集中在客户端登录界面、本地账号记录读写和登录成功处理。主要关注成功回执对应的提交数据、多个账号的切换以及同名账号更新。无跨服务端协作需求，不拆分 task。
