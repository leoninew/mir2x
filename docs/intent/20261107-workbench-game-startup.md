# Intent / 意图：工作台游戏启动改进

最后修改时间: 2026-11-07 15:05:03

## Review status / 审查状态

Accepted

## Background and goals / 背景与目标

- 工作台直接启动客户端、服务端时不出现额外控制台，保留游戏图形窗口。
- 一次点击自动启动服务端，区分进程存活与玩家端口监听，并可查看启动日志。
- 关闭并重新打开 Workbench 后，仍能识别此前由 Workbench 启动且仍在运行的客户端和服务端。
- 修复原服务端手动 Launch 替换 Server 时丢失已加载玩法配置的问题。

## Non-goals / 非目标

- 不改直接启动 EXE 时的 Windows 子系统；不增加网络、并发或启动参数配置。
- 不宣称端口监听表示地图、任务完全就绪；不操作真实账号或游戏数据，也不扫描/停止未由 Workbench 记录所有权的外部进程。
- 不仅凭进程名称或端口扫描、停止外部进程；旧版 Workbench 启动且未留身份记录的进程不自动视作本程序所有。
- 不新增页面或反向、性能测试；仅扩展运行页以准确表达已恢复及身份未知的进程状态。

## Scenarios / 场景

- 在工作台启动两个程序；原游戏窗口正常显示，不出现控制台。
- 服务端直接自动运行；界面显示进程和端口监听状态，日志可供排障。
- Workbench 退出后重新打开；由当前版本记录且仍存活的进程保留 PID、运行状态和停止能力。
- 进程已退出、PID 被复用或身份无法验证时，不把其他进程显示或操作成本工作台所启动。
- 使用服务端原窗口手动 Launch 时保持初始化的玩法配置。

## Acceptance criteria / 验收标准

- A01：Workbench 启动时 Windows 控制台不出现，服务端使用既有自动启动参数。
- A02：标准输出/错误可按进程类型查看；显示进程与 PID 归属的监听状态，无法判断时不冒称监听。
- A03：手动启动复用原 Server，保留玩法快照；自动启动不受影响。
- A04：正常路径定向检查通过，完成匹配服务端和工作台构建安装，保留现有配置、停止行为与用户文件。
- A05：将受管理进程的 PID、规范化可执行文件路径和创建时间持久化；Workbench 重启后仅恢复三项身份均匹配且仍存活的进程。
- A06：清理已退出或身份不匹配的陈旧记录；身份无法验证时标记为状态未知、不发停止信号，也不以端口或文件名接管进程。
- A07：升级前已运行但没有持久记录的进程不自动接管；从此版本启动的进程可在之后的 Workbench 会话恢复。

## Workload and decomposition / 工作量与拆分

涉及 Python 进程记录与身份校验、Vue 未知状态表达、安装时保留运行数据、服务端生命周期回归和构建验证；工作量中等，边界可由主会话串行处理，不拆 task。按既有所有权约束，不扫描或接管旧版及外部进程，没有待裁决项。

## Questions and decisions / 问题与决策

- 用户要求本会话记录并实施；控制台隐藏仅针对工作台拉起的进程。
- 仅显示端口监听，不将其等同地图全部加载；保留手动入口并修复快照丢失。
- 仅恢复由当前版本持久记录且身份验证通过的进程；没有记录的升级前进程不会被追认或接管。

## Risks / assumptions / 风险 / 假设

- 自动启动不通过密码窗口；该输入被 NPC 加密路径使用，特殊加密 NPC 需单独验证。
- 外部服务端进程不由当前工作台接管；停止功能现有行为不变。
- 游戏日志可能包含运行信息，日志目录应视为本机数据。
- 升级前已启动且没有持久记录的进程无法区分手动启动与旧版 Workbench 启动；需要用户在升级后从 Workbench 重新启动时才纳入跨会话管理。
