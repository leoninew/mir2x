# Intent / 意图：工作台玩法配置备份与还原
最后修改时间: 2026-11-07 00:33:22

## Review status / 审查状态

Accepted

## Background and goals / 背景与目标

- 在 Mir2x Workbench 中为当前管理的玩法配置目录提供集中备份与还原。
- 创建备份时自动用本地时间戳作为名称，并可填写说明；界面能查看已有备份并选择还原。
- 将备份放在工作台应用目录下的集中存储中，而不是继续散落在玩法配置目录。

## Non-goals / 非目标

- 不包含 `install/server/mir2x.db3` 角色存档数据库，也不备份整个 server 目录。
- 不提供删除、导入/导出、自动定时备份或跨版本迁移功能。
- 不修改玩法配置计算逻辑，不要求即时生效；还原后的玩法配置由服务端下次启动读取。
- 不纳入编辑器内未保存草稿；备份和还原针对磁盘上的完整 `server/config/gameplay` 目录。

## Scenarios / 场景

- 用户在已绑定的玩法配置工作区点击“备份管理”，查看备份时间、说明并创建备份。
- 用户确认还原某个备份；还原前自动创建当前磁盘目录的安全备份。
- 若当前存在未保存草稿，确认还原时明确告知该草稿会被丢弃；成功后刷新工作区，避免旧草稿复写被还原的数据。
- 校验损坏或不适用于当前配置格式的备份时，不替换当前目录。

## Acceptance criteria / 验收标准

- A01：创建的备份在应用目录的集中位置，以时间戳自动命名，保留说明和完整玩法目录快照。
- A02：工作台列出备份，能选择有效备份还原到当前绑定的 `server/config/gameplay`。
- A03：还原先自动备份当前数据；仅在快照校验通过后替换目录，失败时原目录可恢复。
- A04：成功还原后旧工作区请求失效，前端清除旧草稿并重新读取。
- A05：不处理角色数据库或任意用户路径；相应的定向检查、前端类型检查、构建和工作台发行安装完成。

## Workload and decomposition / 工作量与拆分

跨 Python 文件快照服务、固定工作区 API、Vue 管理界面和工作区草稿生命周期，复杂度中等；完整校验、目录替换回滚和草稿失效是主要风险。职责边界清晰且需要共享协调，无需拆分 task。

## Questions and decisions / 问题与决策

- 用户确认“数据目录”是当前工作台管理的 `server/config/gameplay`，不含角色存档。
- 用户决定备份名称使用自动生成的时间戳。
- 备份记录原服务端目录；还原只允许应用到同一服务端，避免切换目录后误还原到另一套配置。

## Risks / assumptions / 风险 / 假设

- 集中存储位于工作台应用目录 `backups/gameplay`；该目录需要可写磁盘空间。
- 配置目录被外部程序同时改写时，工作台锁无法阻止外部竞争；复制后仍校验快照，目录替换失败会回滚。
- 还原只恢复配置文件，不自动重启服务端；正在运行的服务端进程不受即时变更影响。
- 本期不提供备份删除/保留策略；快照持续占用应用目录磁盘空间。

## 路径配置统一（替代前条 YAML 预置方案）

用户要求改进：路径集中在 Workbench 自己的 game-launch.json，新增 server_config_path，默认 ../server，支持 UI 编辑且下次打开生效。旧 JSON 升级保留启动路径，只在缺字段时迁移旧 gameplay.root；以后 JSON 是桌面目录唯一来源。首次安装复制预置 JSON，已有文件不覆盖。目录不可用时允许进入设置修正。检查仅正常迁移、持久化及桌面绑定与必要静态检查，最终统一构建安装；不启动 client/server。
